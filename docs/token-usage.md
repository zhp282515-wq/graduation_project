# 管理员 Token 用量

管理员登录后从左侧「用量」进入 `/admin/usage`。Docker 默认地址为 `http://127.0.0.1:8080/admin/usage`。本地开发沿用 README 中的 Vite 和 FastAPI 启动方式。常规 Docker 更新使用 `docker compose up -d --build backend frontend`。

## 数据与接口

每次调用记录用户、调用时角色、业务会话（独立检索和入库可为空）、模型、来源、输入、输出、总量、估算标志和 UTC 时间。明细与上海自然日的按账号、角色汇总用同一条 SQL 原子写入。账号没有关联删除外键。只有供应商确认的用量进入日汇总、环比、趋势、活跃人数和榜单。两表默认持续保留。异步写入报错记服务端日志，正常关闭会排空写入任务；进程被强杀可能丢失尚未写入的记录。

聊天、工具后续轮次、重新生成、兜底摘要、历史压缩、后台记忆、知识库批量嵌入与重排分别计数。供应商 usage 优先。流中间重复的累计 usage 只取最终有效值。部分输出后断流且没有 usage 时按已接收内容估算。离线分词估算按单个中日韩汉字、最多四个 ASCII 字母数字、单个其余非空白字符切分；内嵌图片按固定近似值处理。估算调用仅进入明细，标记 estimated，不进入看板。只收到总数时直接采用该整数，并将无法证实的输入输出拆分显示为「未拆分」。概览卡片和用量榜直接显示带千位分隔符的完整整数。

健康检查与直接运行的脚本没有已认证的请求归属。使用正常 HTTP 登录进行压测时，使用专用账号，启动后端前通过环境变量 `TOKEN_USAGE_EXCLUDED_USER_IDS` 配置其用户 ID（逗号分隔）。该列表也用于历史回填。无法从普通业务请求自动识别共用同一账号的人工访问与压测。

三个 GET 接口均位于 `/api/admin/usage` 下，支持 `role=all|user|admin`。概览使用 `overview`，30 日趋势使用 `trend`，榜单使用 `ranking?days=1&offset=0&limit=5`。榜单允许 1、7、30 天和每页 1–100 条。排序先看用量，再用稳定的内部账号 ID 打破平局。API 只输出脱敏名称和统计字段。角色变更前后的用量按各自发生时的角色计算，全部角色榜单合并同一账号。禁用或已删除的账号显示「已注销用户」。

服务端缓存 45 秒，跨上海午夜立即更新。页面每 60 秒刷新，手动刷新也遵循服务端缓存。今日对比昨日相同时段，7 / 30 天对比此前连续的 7 / 30 个完整自然日。没有调用的日期使用空值，上一周期为零时不计算百分比。

## 上线、历史与回滚

后端启动时自动执行 `session/usage_schema.sql`，创建明细表、日汇总表、索引和上线时间标记。首次上线后可执行：

```powershell
docker compose exec backend python -m scripts.backfill_token_usage
```

脚本只读取上线前的消息 ID、归属、时间及 token 字段。只有末轮输入与输出之和等于历史总量、账号角色可核实且会话未经重新生成，才收录一条历史记录，模型名标记为「历史未记录」。早期没有用量或不可还原的调用保留空缺。重复运行按历史消息 ID 去重。

需要回滚时先切回旧版应用。可保留新增表；需要清除这些统计数据时，备份后在同一数据库执行 `scripts/rollback_token_usage.sql`。该脚本会删除本功能的三张表。

## 独立开发库预览

在本机 PostgreSQL 建立名称以 `_dev` 结尾的开发数据库，按项目既有流程初始化真实可登录的管理员。将当前开发终端的 `LANGGRAPH_POSTGRES_URI` 指向该库，再执行：

```powershell
$env:APP_ENV = 'development'
uv run --locked python -m scripts.seed_token_usage
```

按同一开发库配置启动后端。生成器创建 9 个无可用密码的示例身份，覆盖最近 60 个自然日，特意留出几个空白日；每次使用稳定的事件 ID。生产标志、非本机地址和非开发数据库会触发拒绝。示例数据只用于独立开发库。
